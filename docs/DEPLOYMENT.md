# Развёртывание BALANCE: Supabase + Vercel

Платных действий и изменений во внешних аккаунтах не выполнялось. Ниже — порядок действий для владельца.

## 1. Supabase (база, авторизация, хранилище)
1. Создать проект (Free) в регионе, выбранном с учётом аудитории и требований к данным (см. §5).
2. Применить миграции: `pnpm exec supabase link --project-ref <ref>` → `pnpm exec supabase db push`
   (создаются таблицы, RLS, функции, бакет `media`, справочники).
3. Authentication → URL Configuration: Site URL = `https://<домен>`, Redirect URLs = `https://<домен>/**`.
4. Authentication → Email: включить подтверждение email; пароль ≥ 8 символов, буквы и цифры.
   Встроенный SMTP Supabase ограничен по количеству писем — для запуска подключить собственный SMTP
   (провайдер выбирает владелец; ключи — только в настройках Supabase).
5. Первый владелец: зарегистрироваться на сайте, затем выдать роль в SQL Editor:
   `insert into user_roles (user_id, role) select id, 'owner' from auth.users where email = '<email>';`
   Дальше роли (editor, reviewer) выдаются в админке → «Пользователи и роли».
6. Контент: `SUPABASE_DB_URL=… NEXT_PUBLIC_SUPABASE_URL=… SUPABASE_SECRET_KEY=… pnpm db:seed --content-only --allow-remote`
   (импорт от имени служебного editor-аккаунта; тестовые пользователи НЕ создаются).
   По умолчанию `allow_unreviewed_publish = false`: без утверждения преподавателем контент не публикуется.
   Если владелец решит запускаться до экспертной проверки — включить в админке «Настройки» (страницы покажут предупреждение).

## 2. Vercel (приложение)
1. Импортировать репозиторий; Framework = Next.js; Build = `pnpm build`; Node 22.
2. Переменные окружения (Production и Preview):
   - `NEXT_PUBLIC_SITE_URL` = `https://<домен>`
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   - `SUPABASE_SECRET_KEY` (только серверная; без префикса NEXT_PUBLIC)
   - `NEXT_PUBLIC_MEDIA_BASE_URL` — пусто (медиа из `public/media` раздаёт CDN Vercel) или URL другого хранилища/CDN.
3. Сборка требует доступа к Supabase (пререндер страниц из опубликованного контента).
4. После деплоя: проверить `/ru`, `/en`, регистрацию (письмо приходит, ссылка ведёт на `/auth/callback`), админку.

## 3. Медиа
- 3D-анимации, постеры и кадры лежат в `public/media/poses/<slug>/` и попадают в деплой: 44 асаны ≈ 14 МБ (MP4 6,2 МБ, WebM 4,9 МБ, WebP 1,8 МБ; ≈ 300 КБ на асану), брендовые иллюстрации ≈ 0,25 МБ. Видео загружается только по нажатию.
- Загрузки из админки идут в Supabase Storage (бакет `media`, публичное чтение, запись — editor/owner).
- Хостинг можно заменить без правки страниц: `NEXT_PUBLIC_MEDIA_BASE_URL` + `mediaUrl()`.
- Мастер-файлы Blender (`pipeline/out/**`) не публикуются и не коммитятся; они воспроизводимы из `pipeline/poses/*.json`.

## 4. Ограничения бесплатных тарифов (по данным на ноябрь 2026 — сверить с официальными страницами перед запуском)
| Сервис | Лимит | Риск для BALANCE |
|---|---|---|
| Supabase Free | 2 активных проекта, БД 500 МБ, Storage 1 ГБ, egress ~5 ГБ/мес (+5 ГБ cached), 50 000 MAU | **Проект ставится на паузу после 7 дней без активности** — сайт перестанет отвечать на запросы к данным, пока проект не будет восстановлен. Для публичного запуска нужен Pro ($25/мес) или регулярная активность. |
| Vercel Hobby | 100 ГБ Fast Data Transfer, 1 млн вызовов функций/мес | **Только некоммерческое использование.** Если проект коммерческий — нужен Pro ($20/пользователь/мес). |
| Встроенный SMTP Supabase | очень малый лимит писем | Нужен свой SMTP для подтверждений и восстановления паролей. |

Источники (сторонние сводки, официальные страницы в поиске не открылись): jetadmin.io, toolradar.com, activepieces.com (Supabase); vercel.com/docs/limits, vercel.com/docs/plans/hobby, fencode.dev (Vercel).

Резервное копирование без платных функций: `pnpm db:backup` (schema + data, локально или `SUPABASE_DB_URL=…`),
восстановление: `scripts/restore.sh backups/<ts>` после применения миграций. Учения по восстановлению проведены
локально — см. `docs/QA_REPORT.md`. Бэкапы содержат персональные данные (email, хеши паролей): хранить зашифрованно.

## 5. Доступность и юридические вопросы (НЕ решены — нужен владелец/юрист)
- **Россия:** по открытым данным 2026 г. YouTube в РФ ограничен (в феврале 2026 домен удалён из НСДИ, далее
  частичные ограничения); российские провайдеры в 2025 г. замедляли соединения с Cloudflare и рядом зарубежных
  хостингов. Перед запуском проверить реальную доступность сайта, Supabase и видео из РФ и из других стран.
  Архитектура уже допускает: видео по нажатию со ссылкой-фолбэком; провайдеры `vk`/`rutube` для RU-уроков;
  замену хостинга медиа.
- **Персональные данные:** соответствие GDPR, 152-ФЗ (в т. ч. локализация данных граждан РФ) или другим законам
  НЕ заявляется. Нужно решение о юрисдикции оператора, регионе хранения, уведомлении РКН (если применимо),
  юридическая проверка политики конфиденциальности и условий (сейчас это помеченные черновики).
- Реальные контакты и соцсети проекта не известны — страница контактов показывает, что они появятся позже.
